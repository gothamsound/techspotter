# TechSpotter — build brief

You are building **TechSpotter**, a single-page web applet published on GitHub Pages
(github.io). It ingests an entire screenplay PDF **entirely in the browser** and
produces the **scene × character matrix** used to prep a livestreamed table read —
plus two optional department layers: **Sound** (playback / phone calls / sound
reactions) and **Video** (phone screens / TV screens / video playback). It is a
sibling of `sides-enlarger` and follows the same hard rule: **all processing is
local; the script never leaves the machine.**

The audience is a production/AV crew prepping a table read: they need to know who
speaks in every scene, and which scenes need the sound or video department to
prepare something before the read goes live.

---

## 1. Hard constraints (non-negotiable)

1. **100 % client-side.** Static site (plain HTML/JS/CSS or a light build step),
   hostable on GitHub Pages. After initial page load there are **zero network
   requests** — no analytics, no fonts from CDNs at runtime (bundle or
   system-stack them), no telemetry. The PDF is read via the File API and never
   uploaded anywhere. State lives in memory (optionally localStorage for UI
   prefs only — never script text).
2. **Copyright posture:** the repo must never contain a real screenplay. All test
   fixtures are synthetic PDFs generated by a script in the repo (see §8).
3. **No accounts, no server, no build-time secrets.** Open the page, drop a PDF,
   work, export, close.

## 2. Tech directives

- **PDF text extraction: `pdf.js`** (Mozilla), bundled locally. You need text
  runs **with coordinates** (x/y per item) — layout position is load-bearing for
  parsing (indent bands distinguish cues/dialogue/action; the page-number zone
  matters). Do not use a text-only extractor.
- **Exports:** CSV always; XLSX via a bundled SheetJS; print stylesheet for a
  clean letter-landscape matrix (repeat header row per page; hide all chrome).
- Keep the core parser a **pure module** (text-runs in → structured show out),
  unit-testable in Node without a browser.

## 3. The screenplay parser (this knowledge is hard-won — implement it faithfully)

Parse the PDF into: `scenes[] { id, heading, page, characters_speaking[],
action_text, dialogue_by_character }` + `characters[]` + review lists (§3.4).

### 3.1 Scene headings
- **Numbered production drafts:** headings carry scene ids (`14  INT. LAB - NIGHT`
  or trailing numbers; ids may be alphanumeric — `22A`, `29A` — **treat scene ids
  as strings everywhere**, never parse to int).
- **Unnumbered table-read exports exist** (bare slugs: `INT. EVIDENCE LAB - NIGHT`,
  no numbers anywhere). Pre-scan the document: if **no** numbered heading exists,
  enter bare-slug mode and assign sequential ids 1..N. If numbered headings
  exist, a stray all-caps slug inside action is context, NOT a boundary.
- Slug test: starts `INT.` / `EXT.` / `INT./EXT.` (and `I/E.`), all-caps, ≤ ~90
  chars. Beware: `INTO...` is not `INT.` — require the dot/boundary.
- **A parse that finds zero scenes must fail loudly** with a visible error —
  never render an empty matrix silently.

### 3.2 Character cues (who speaks)
A cue is an all-caps line in the cue indent band, followed by dialogue. Gates —
keep them strict, and **surface what they reject** (§3.4) instead of loosening:
- Charset `[A-Z0-9 .'\-]` — this **rejects** `MERC #1` (`#`) and `GIRLS/CASSIDY`
  (`/`): real characters lost this way in live shows. Hence the reject rail.
- Strip trailing parentheticals from the cue line: `(V.O.)`, `(O.S.)`, `(CONT'D)`,
  `(O.C.)` — same character.
- Stop-words that mark non-cues (`AND`, `FROM`, …) — but know `ELEANOR FROM HR`
  was a real character rejected by `FROM`. Reject-with-reason, don't drop.
- Width/position: dual-dialogue side-by-side headers (`LOLA        DENNY`) won't
  parse as one cue — surface, don't guess.
- **Single-glyph cues are watermark debris** (per-page recipient-name watermarks
  land capital letters in the cue band on *every* page — one real script had "S"
  speaking in 52 scenes). Gate-reject single glyphs but surface them (a genuine
  one-letter character — Bond's M — must never be a silent miss).
- **Title/furniture lines are never cues:** `EPISODE 101`, `ACT 2`, `PART TWO`,
  `DAY 3`, transitions (`CUT TO:`), and any line already seen on the title page /
  running headers.

### 3.3 Character identity
- Names normalize to uppercase, trimmed.
- **Variant qualifiers = distinct performers by default**: `YOUNG VALERIE`,
  `VICTOR'S TEXT`, `MERC #1`, `X (V.O.)`-beyond-tag-strip stay separate columns.
- Same-person guesses (`VICTOR HALE` ⊂ `VICTOR`, extra token is a surname-like
  real name part) are **offer-only merge suggestions**: canonical = the name used
  in more scenes, two-click confirm, dismissible. Never auto-merge.

### 3.4 Review rails (the applet's honesty layer)
Alongside the matrix, render dismissible review chips:
- **Rejected cue-shaped lines** with the failed gate named (`charset '#'`,
  `word 'FROM'`, `wide (dual dialogue?)`, `single letter (watermark?)`) — only
  when cue-positioned AND followed by dialogue-band text (noise filter). One
  click adds the name as a character and marks its scenes by text search.
- **Merge offers** (§3.3).
- Chips are suggestions; the operator's click is always the authority.

### 3.5 Page numbers
Printed page = the running-header zone (top ~72 pt). Body sentences ending in
numbers ("Bro, I'm 18.") beat naive bottom-most/last-match rules — header zone
wins; footer only as fallback.

## 4. Sound department layer (toggle)

Scan each scene's **action text + parentheticals + dialogue context** for moments
the sound crew must prep. Three categories, each with badge + per-moment evidence
(snippet, page, matched trigger):

1. **`playback`** — singing, dancing, music performance (needs backing
   tracks/playback at the read). Triggers: sing/sings/singing/hums/humming/
   song/dances/dancing/karaoke/piano/guitar/band/DJ/jukebox/"MUSIC"/music
   cue/needle drop/anthem/lullaby; `(singing)`/`(sings)` parentheticals; quoted
   song titles near those verbs; lyrics blocks (indented italic/quoted runs).
2. **`phone`** — phone calls (that actor's mic gets phone-voice processing; a
   far-end voice may need casting/feeding). Triggers: phone rings/answers/
   dials/hangs up/speakerphone/voicemail/`(into phone)`/`(on the phone)`/
   `(over phone)`/INTERCUT — PHONE/FaceTime/calls [NAME]. Tag which characters
   are on the call when attributable.
3. **`sfx-reaction`** — a character significantly reacts to a sound (the sound
   must be played for the reaction to land). Two signals combined:
   - **The caps convention:** in action lines, screenwriters capitalize sounds —
     "a KNOCK at the door", "the PHONE RINGS", "a GUNSHOT". Flag all-caps runs
     (≥1 word, not a character name from §3, not a slug) inside mixed-case
     action sentences.
   - A **sound lexicon** (knock, gunshot, shot, explosion, siren, alarm,
     doorbell, crash, thud, scream, shatter, honk, buzz, ping, chime, click,
     bang, slam, footsteps, o.s./O.S. sounds) — plus reaction verbs near them
     (hears, reacts, startles, jumps, spins, turns toward, freezes, ducks).

**Bias: recall.** A false flag costs a click; a missed singing scene costs a
live scramble. Rank by confidence (lexicon+reaction-verb > caps-run alone), let
the operator dismiss per moment; dismissed state persists for the session and
rides the export as `dismissed`.

## 5. Video department layer (toggle)

Same mechanics, categories:
1. **`phone-screen`** — text messages shown, phone screens: ON THE PHONE
   SCREEN/INSERT — PHONE/text message/texts/we see the screen/iMessage/lock
   screen/swipes/scrolls.
2. **`tv-screen`** — television/monitor content: ON TV/television/TV/monitor/
   newscast/news report/broadcast/ANGLE ON the TV/footage plays on.
3. **`video-playback`** — any other played video: footage/video/watches [footage]/
   security cam/CCTV/Zoom/video call (also tag `phone` if it's a call)/
   projector/screening/playback/INSERT — SCREEN/laptop/iPad/tablet screens.

Overlaps with Sound are expected and correct (FaceTime = `phone` + `video-playback`).

## 6. UI

- **Drop zone** → parse with a per-page progress bar (big PDFs, main-thread
  friendly: use a worker).
- **The matrix:** rows = scenes (id + slug + page), columns = characters
  (scene-count ordered). Cells toggle on click (operator judgment beats parse).
  Column headers: click to rename, two-step to delete (delete = the expensive
  mistake; make it deliberate). An "add character" affordance with auto-mark by
  word-boundary text search across scenes, operator adjusts before commit.
- **Department toggles** add badge columns per scene: 🔊 with count, 🎬 with
  count. Clicking a badge opens that scene's moment list: category, snippet
  (±1 line context), page, dismiss button.
- **Review rails** (§3.4) above the grid.
- Look: clean, dense, print-friendly; dark theme welcome; touch-usable (iPad).
- Everything exportable: matrix CSV/XLSX (one sheet for the matrix, one per
  department with scene/category/snippet/page/dismissed), plus print.

## 7. Non-goals (v1)

- No revision-diffing between drafts. No OCR (text-layer PDFs only — detect an
  imageonly PDF and say so plainly). No server features of any kind. No
  auto-merge of variant names. No attempt at perfect department detection —
  the review UI is the product; the detectors just fill it well.

## 8. Acceptance tests (synthetic fixtures — generate, don't copy)

Write a Node script that *generates* small synthetic PDFs exercising every rule,
and assert on parser output (pure module, no browser):
1. Numbered draft, 5 scenes incl. `22A` → ids as strings, correct speakers.
2. Bare-slug table-read export → sequential ids; same doc with ONE numbered
   heading → bare slugs in action do NOT open scenes.
3. `MERC #1` + `ELEANOR FROM HR` + `GIRLS/CASSIDY` cues → absent from matrix,
   present in the reject rail with correct reasons; one-click add works.
4. Watermark letter on every page in the cue band → rejected as
   `single letter (watermark?)`, shown once, not 52 chips.
5. `VICTOR HALE` (1 scene) + `VICTOR` (20) → merge offer, canonical VICTOR;
   `YOUNG VALERIE` + `VALERIE` → **no** offer.
6. Sound: a scene with "She SINGS 'Happy Birthday'", one with "the PHONE RINGS.
   Marta freezes.", one with "a distant GUNSHOT. Everyone ducks." → correct
   categories + snippets; a scene with the character name in caps mid-action →
   NOT flagged as sfx.
7. Video: "ON THE TV: a newscast", "INSERT — PHONE SCREEN: a text from MOM",
   "They huddle around the laptop, watching the footage" → correct categories.
8. Zero-scene PDF (a novel manuscript) → loud failure, no empty matrix.
9. Export round-trip: CSV/XLSX cell values match the grid incl. operator edits
   and dismissed flags.
